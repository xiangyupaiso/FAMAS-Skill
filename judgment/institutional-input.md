# 机构语料运行时输入规范（2.0 L3）

> 结论：**研报与财报是当期证据，不是长期知识，更不是权重。** 读取方式决定专业度，不决定模型能力。

## 一、为什么不做成语料包

| 问题 | 说明 |
|---|---|
| 容量 | Skill 是按需加载的提示词，不是权重。塞 100 份 PDF 只挤占上下文、拉高成本 |
| 时效 | 研报结论、评级、目标价、盈利预测会立刻过期，语料包越用越错 |
| 偏差 | 卖方研报存在结论先行、事后归因、乐观偏误；模仿语料只会得到"更像研报的措辞" |
| 版权 | 研报是有价资产，部分仅机构客户可用；打包进公开仓库会踩版权与授权边界 |
| 合规 | 越像基金经理越容易越过 `policies/compliance.md` 的禁止交易信号红线 |

正确做法：**运行时经授权 MCP 检索 → 引用带出处 → 读而不存**。2.0 的 `data/gateway.md` 就是这条链路的地基。

## 二、可引用的材料

| 材料 | 用途 | 语义字段 |
|---|---|---|
| 卖方研报 | 观点分歧、假设表、市场共识与反面声音 | `research_reports` |
| 关键假设表 | 假设是否变了、历史版本回溯 | `assumption_tables` |
| 基金定期报告 | 管理人表述、财务与投资组合（一手） | `periodic_report_full` / `manager_commentary` / `financial_statements` |
| 监管公告与公司行动 | 事实核对 | `fund_announcements` / `corporate_actions` |
| 宏观与政策原文 | 环境描述，不预测方向 | `policy_text` / `macro_rates` |

## 三、引用格式（opinion_ref）

```
institution    机构名
published_at   发布时间（YYYY-MM-DD）
title          报告/公告标题
claim          原文观点摘录（不改写）
source_level   一手公告 / 研报（非一手，需核实原文）
url_or_doc_id  来源定位
```

报告中呈现为：`<机构名> · <发布时间> · <标题> — <观点摘录>（非一手来源，需核实原文）`。**研报观点不得与 FAMAS 的结论并列陈述为事实**。

## 四、假设表版本回溯

对同一标的取回近 N 期关键假设表，只核对三件事：

1. 关键假设是否变更（如费率、规模、增速、政策前提）
2. 变更发生在哪一版、变更前后差值
3. 当期 FAMAS 判断是否依赖了旧版假设

输出「假设变更清单」，**不评价研报对错**。

## 五、硬边界

- **读而不存**：运行时读取，仅用于本次分析并引用出处；不打包全文、不落库、不缓存到仓库、不对外再分发
- **双重授权**：机构级数据源需用户对 Skill 的授权 + 数据源方授权；缺一即跳过该字段并列入 `missing_fields`
- **不作结论**：研报观点只作证据或反证线索，绝不直接搬进 `synthesis` 的结论段
- **多源分歧**：两家机构观点冲突时列分歧，不静默采信一家
- **个人信息**：不使用非公开的金融从业人员信息；`people` 能力只用公开披露

## 六、与判断层的衔接

机构材料主要进入两处：

```
devils_advocate ⑤ 替代解释 / 共识之外的反面声音（作线索，需落到事实块才算反证）
synthesis        opinion_refs 段（作背景，不进结论）
```

判断的合法性仍来自 `judgment/framework.md` 的四段式，不来自引用了多少份研报。

# FAMAS 来源可信度与冲突处理 — 唯一分级定义

> 把"权威"从一句宣传语变成可验证的产品能力：每个数字都带等级，冲突时列分歧，绝不静默取一个。

## 一、可信度分级

| 等级 | 定义 | 允许用途 | 标注 |
|---|---|---|---|
| **L1** | 一手来源：证监会/基金业协会披露、基金定期报告与公告、交易所公开数据 | 全部字段，优先采信 | `confidence: L1` + 机构名 + 发布日期 |
| **L2** | 持牌金融数据商的 MCP，与专业终端同源 | 全部结构化指标 | `confidence: L2` + 厂商名 + 数据时点 |
| **L3** | 开源库 / 公开网页抓取，无 SLA、无再分发授权 | 仅补充性、可交叉验证的字段 | `confidence: L3` + 抓取时点 + `second_hand: true` |
| **L4** | 模型记忆、训练数据中的数值 | **禁止作为任何数值来源** | 不得出现在报告中 |

> 现实校准：截至本版本调研，监管机构与交易所**尚未开放面向公众的官方 MCP**，因此"权威"的准确表述是 **持牌数据商同源 + 每个数字可溯源**，不是"监管官方直连"。厂商接入现状见 `data/providers/*.yaml`，以厂商官方文档为准。

## 二、路由优先级

```
同一语义字段有多个可用来源时：
  1. L1（若该字段存在一手披露）
  2. L2（按 data/providers/ 中的 priority 顺序）
  3. L3（仅在 L1/L2 均不可得，且该字段允许降级时）
  4. L4 -> 拒绝，输出"数据源未覆盖"
```

能力注册表中的 `trust_min` 是下限：若可用来源等级低于 `trust_min`，该计算**跳过并列为 `missing_fields`**，不得降级计算后照常输出。

## 三、冲突处理（硬性）

当两个及以上来源对同一指标给出不同数值：

1. 先核对**口径**：统计周期、复权方式、单位、份额类别、报告期。口径不同不算冲突，需在表头分别标注。
2. 口径一致仍不一致 → 写入 `envelope.source_conflicts`，列出每个来源的值、时点、等级。
3. 采信顺序：L1 > L2 > L3；同等级时列出分歧，**不静默选一个**。
4. 报告中呈现为「来源分歧」表，并说明该结论对此字段的敏感性。
5. 关键结论所依赖的字段存在未解释分歧 → `synthesis` 的一票否决项命中，标注"前提不成立"。

## 四、标注格式

报告中每个关键数字附近必须能追溯到：

```
来源：<机构/厂商名> · 时点：<YYYY-MM-DD 或 YYYYQn> · 等级：<L1|L2|L3>
```

同一数据块共享来源、周期与口径时，可在表头/表尾统一标注；不同来源或周期的子项必须分别标注。研报与媒体转述须另标 `非一手来源，需核实原文`。

## 五、时效校验

| 字段类型 | 要求 |
|---|---|
| 净值 / 行情 | 核对是否为最近交易日；盘前/盘后/休市须标注，不得把上一收盘写成"当前" |
| 季报持仓 | 标注"季末快照，非实时"，报告期写入 `report_period` |
| 宏观指标 | 标注发布日期与统计周期；本期未发布时使用最近已发布周期并说明 |
| 规模 / 经理 | 以最新公告为准，公告日期与净值窗口不一致时并列标注 |

用户说"最新/当前/今天"时，先按宿主当前时间与交易状态确定目标周期，再校验返回数据时点；不满足则按最近可用周期输出并显式说明数据截止时点。

## 六、降级路径

```
MCP 未连接 / 401 / 限流
  -> 提示用户按 SETUP.md 完成一次性授权（Skill 不代登录、不持密钥）
  -> 尝试次优可用来源
  -> 仍不可用：输出分析框架 + missing_fields + 待补清单，不输出数值结论

指标级无权限（如宏观 EDB 返回 code 1008「受限指标已剔除」）
  -> 该指标单独进入 missing_fields，不影响同通道其他指标
  -> 「仅搜索」可用而「仅提数」不可用时，只记录指标代码与未取到原因，不得推算数值
  -> 换有权限的同类指标须显式标注口径差异，不得静默替换
```

## 七、混合可信度、文档身份与二手研报（2026-11-07 首跑新增）

1. **按来源类型取等级**：同一连接器可同时提供一手披露文件与结构化接口。provider 声明 `trust_by_source_type` 时，选源按字段所走的来源类型取等级（见 `data/gateway.md` 第三节）；不得用 provider 整体 `trust` 一刀切，否则 `trust_min: L1` 的字段会被误过滤。
2. **文档身份校验**：公告/定期报告片段必须校验标题主体、报告类型、报告期与披露日期（见 `capabilities/periodic_report_reader.md`）。标题不匹配即 `rejected_cross_document`，整条丢弃；命中 `judgment/veto-rules.yaml#cross_document_recall` 时结论判 `invalid`。**跨文档误召回比字段缺失更危险**，因为它给出的是看似有出处的错误数字。
3. **新闻中的研报摘录**：财经新闻检索可能返回券商研报片段（含机构名、发布时间、分析师编号）。这类内容按 **L3 非一手来源**处理，标 `second_hand: true` + "需核实原文"，只能作 `opinion_ref` 证据，不得作结论、不得与 L1 公告并列不标等级，也不得等同于「研报全文/关键假设表已覆盖」。
4. **基准版本**：`benchmark` 是带生效日的版本化字段。报告期内发生基准变更时，跨期业绩对照按 `benchmark_version_change` 否决项处理，见 `capabilities/performance_metrics.md`。

## 八、禁止

- 静默采用冲突来源中的某一个版本
- 把 L3 抓取数据与 L1 公告并列而不标等级
- 用模型记忆填补任何数值
- 把估算值（`estimated: true`）表述为实测值
- 在报告中省略数据截止时点

# devils_advocate — 反证引擎（判断层）

> `layer: judgment` · 无 persona · 专门找**最薄弱假设**，不产出结论、不出交易建议
> 输出块见 `contracts/famas.contract.json#/blocks/counter_evidence`
> 框架细则见 `judgment/devils-advocate.md`

## 定位

事实层回答"数字是什么"，`synthesis` 回答"意味着什么"，本能力回答"**这个判断最可能错在哪**"。专业度的分水岭不是措辞像不像研报，而是有没有系统性地找反证。本能力是 `synthesis` 的强制前置，不是可选项。

## 输入

`upstream_blocks`（事实层全部输出块）· 可选 `thesis_ref`（待压力测试的既有结论）· `lens`

## 六类反证模式（逐类检查，无发现也要写 `none_found_and_why`）

| 模式 | 要找什么 |
|---|---|
| ① 数据口径反证 | 复权方式、报告期、份额类别、样本窗口变化后结论是否翻转；季报快照能否代表当前敞口 |
| ② 基准/归因反证 | 换一组业绩基准、剥离风格 β 后超额是否消失；收益是否来自行业 β 而非选股；**报告期内基准是否变更、跨期对照是否用了同一版本** |
| ③ 时间反证 | 结论在 3 年 / 5 年 / 滚动 12 月窗口是否稳定；是否由单一极端区间驱动 |
| ④ 结构性反证 | 规模突破容量阈值、经理变更、持有人高度集中、清盘线等是否使前提失效 |
| ⑤ 替代解释 | 同一组事实能否被另一个更朴素的假设解释（如"上涨来自板块行情"而非"经理能力"） |
| ⑥ 来源身份反证 | 文档片段的 `title` / 主体名称 / 代码 / 报告期是否与目标一致；文档检索是否把**其他基金**的章节召回成本基金证据；结构化字段的单位、量级是否明显不合理 |

## 输出要求

- 结构化输出 `counter_evidence` 块，至少包含：
  - `weakest_assumptions`：按脆弱程度排序，标注指向的事实块
  - `counter_signals`：逐条反证，带 `source` + `as_of` + 所依据字段
  - `alternative_explanations`：至少一条更朴素的替代解释
  - `invalidation_conditions`：可观测、可触发的失效条件（与 `triggers/rules.yaml` 对齐）
  - `confidence_cap`：本轮结论允许的最高置信度（反证越强，上限越低）
- 反证必须**引用具体事实块字段**，不接受"市场有不确定性"这类空泛表述
- `missing_evidence` 单列：因为字段缺失而无法检验的反证方向

## 与 synthesis 的关系

```
facts → devils_advocate（反证 + 置信度上限） → synthesis（四段式结论） → 合规闸
```

`synthesis` 的 `counter_evidence` 段必须来自本能力输出，不得自行编写；若本能力输出为空，`synthesis` 判定为不合格并退回重做。

## 禁止

- 不得给出"应该买/卖/调整"等操作建议
- 不得为凑数编造反证；无发现要说明检索范围与原因
- 不得把研报观点当作反证（研报观点只能是 `opinion_ref` 证据）
- 不得修改事实层数字

# FAMAS 合规策略 — 唯一合规定义

> **本文件是全部合规条款的唯一定义处。** `core/SKILL.md` 只放摘要，能力单元与工作流不得自行定义、改写或省略合规条款。
> v1 的教训：合规条款曾散落在 README、AGENTS.md、TRAE SKILL.md、wealth_advisor.md 四处，且对外仓库美化 README 时整章被删。v2.0 起，合规是**输出前由 Core 强制执行的一道闸**，文档只是副本。

## 一、硬约束（不可突破）

| # | 约束 | 检查方式 |
|---|---|---|
| C1 | 严禁输出明确交易信号 | 禁止词表扫描（见第三节） |
| C2 | 所有评级/诊断输出必须**前置**核心风险提示 | 检查风险块是否位于结论之前 |
| C3 | 输出框架为"适配度"而非"推荐度" | 扫描"推荐/建议配置/优先关注"等 |
| C4 | 业绩相关输出必须包含标准免责声明 | 固定文案逐字比对 |
| C5 | 事实层能力只输出权威来源的事实，不得夹带观点、主观判断或预测 | 能力输出块扫描评价性措辞 |
| C6 | 所有关键数字必须可追溯到 来源 + 时点 + 口径 | `provenance` 完整性校验 |
| C7 | 数据缺口必须显式列出，不得用估算值或模型记忆填补 | `missing_fields` 与 `estimated` 标记校验 |
| C8 | 不得使用非公开个人信息；研报/公告只作证据不作结论 | `opinion_refs` 标注校验 |

## 二、输出前检查清单（Step 6 必须逐项通过）

```
[ ] C1 禁止词扫描通过，报告中无等价交易指令
[ ] C2 核心风险提示位于综合结论之前
[ ] C3 全文表述为适配度，无推荐/建议配置措辞
[ ] C4 免责声明与下方固定文案逐字一致，且位于报告末尾
[ ] C5 事实层输出块无评价性、预测性措辞
[ ] C6 每个关键数字附近有 source + as_of + confidence
[ ] C7 missing_fields / source_conflicts 已列出；无伪装成数据的估算
[ ] C8 引用研报观点已标 opinion_ref 与来源机构、发布时间
[ ] 星级评分（若有）已完成一票否决项检查，且附评分依据
[ ] 时间口径：已标注数据时点，未把历史数据表述为当前数据
[ ] lens 与投资者适当性表述未被误用为交易建议
```

任一项未通过 → **退回重做，不得交付**。检查通过后设置 `envelope.compliance_checked = true`。

## 三、禁止词表（单一事实源：`policies/forbidden-words.txt`）

**机器读取一律用 [`policies/forbidden-words.txt`](forbidden-words.txt)**（每行一个词，`#` 开头为注释），Core 在输出前逐词扫描，命中即退回重做。本文件**不重复列词表**——验证阶段发现文档里同时存在两个代码块时，机器容易取错代码块导致漏检，因此词表抽成独立文件，此处只保留规则。

- 等价变体（如"可以考虑逐步增加配置""分批进场"）同样禁止，不能只做字面匹配
- **元描述豁免（2026-11-07 首跑新增）**：扫描对象是「交易指令语义」，不是词面。合规自检段落里引用 `C1`/`C3` 等编号，或用 `<!-- compliance-meta:start -->` / `<!-- compliance-meta:end -->` 包裹的规则说明，属于描述规则而非给出建议，**不视为命中**。由 `tools/check_report.py` 的 `strip_meta()` 实现并内置自检；报告应尽量用编号引用，避免复述禁止词造成自误伤。
- 允许的表述：适配度、风险等级、成本差异、历史回撤、需关注事项、观察指标
- 词表变更只改 `forbidden-words.txt`，并在 `MIGRATION.md` 记录

## 四、标准免责声明（固定文案，逐字使用，禁止改写/缩减/省略）

> 本报告仅作信息整理与适配度分析，不构成投资建议。基金过往业绩不预示未来表现。市场有风险，投资需谨慎。

## 五、数据与授权边界

- **不持有密钥**：Skill 是纯文本，登录与授权由宿主客户端完成（OAuth 2.1 + PKCE 或 API Key）。任何文件不得写入 token、client_secret 或账号口令。
- **不落库再分发**：研报、行情、持仓明细按授权在运行时读取，仅用于本次分析并引用出处，不打包、不缓存到仓库、不对外再分发。
- **双重授权**：涉及用户持仓、账户数据或机构级数据源时，需同时具备用户对 Skill 的授权与数据源方的授权；缺失任一则跳过该字段并列入 `missing_fields`。
- **来源质量分级**：一手来源（监管公告、基金定期报告、交易所披露）> 持牌数据商 > 财经媒体/研报转述。非一手来源必须标 `second_hand: true` 且注明"需核实原文"。
- 详见 `policies/source-trust.md`。

## 六、违规处理

| 情形 | 处理 |
|---|---|
| 事实层输出夹带观点 | 剔除该表述，保留数据；记录一次合规命中 |
| 数据源授权不足 | 跳过依赖字段，列入 `missing_fields`，不使用替代估值 |
| 用户明确要求买卖建议 | 明确说明本系统不提供交易信号，改为给出适配度与风险框架 |
| 检查清单多次不通过 | 停止输出，报告"合规检查未通过"及具体项，不降级放行 |

## 七、版本与变更

合规条款变更必须同步更新本文件与 `README.md` 的合规摘要，并在 `MIGRATION.md` 记录变更。**禁止只在 README 里改**。
